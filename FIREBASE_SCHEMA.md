# TruthLens Production Firebase / Firestore Architecture & Schema

**Version:** 2.0.0  
**Status:** Production Ready & Non-Destructively Migrated  
**Database:** Google Cloud Firestore (Document Store)  
**Security Rules:** `firebase/firestore.rules`  
**Index Definitions:** `firebase/firestore.indexes.json`  
**Migration Tool:** `firebase/seed/migrate_schema.py`  

---

## 1. Architectural Principles

1. **Strict Data Segregation**: Admin credentials, administrative audit trails (`system_logs`, `admins`), and user telemetry are secured via Firestore Security Rules and never exposed to unauthenticated users or standard clients.
2. **Normalized Claims & Verification Engine**: Separates incoming submissions (`verifications`), individual normalized assertions (`claims`), corroborating media references (`sources`), and stance citations (`evidence`).
3. **Dual Compatibility & Non-Destructive Migrations**: Production schemas work seamlessly alongside existing local seed databases and legacy routes without deleting or corrupting existing datasets.

## 3. Firestore Compound Indexes (`firebase/firestore.indexes.json`)

To ensure sub-10ms response times for filtered feeds and historical claim lookups, the following compound indexes are configured:

1. **`verifications`**:
   - `verdict (ASC)` + `created_at (DESC)`
   - `input_type (ASC)` + `created_at (DESC)`
   - `status (ASC)` + `created_at (DESC)`
2. **`news_articles`**:
   - `category (ASC)` + `published_at (DESC)`
   - `status (ASC)` + `published_at (DESC)`
3. **`claims`**:
   - `category (ASC)` + `verification_count (DESC)`
4. **`evidence`**:
   - `verification_id (ASC)` + `reliability_score (DESC)`
5. **`sources`**:
   - `credibility_score (DESC)` + `name (ASC)`
6. **`system_logs`**:
   - `admin_id (ASC)` + `timestamp (DESC)`

## 4. Security Rules Summary (`firebase/firestore.rules`)

- **Public Read Access**: `verifications`, `claims`, `sources`, `evidence`, `news_articles`, and public `image_analysis` summaries.
- **Public Submission**: `verifications` and `image_analysis` can be created anonymously or by authenticated users.
- **Strict Admin-Only Boundaries**:
  - `admins/*` → Read & Write restricted to verified administrators (`request.auth.token.role == 'admin'`).
  - `system_logs/*` → Read & Write restricted strictly to administrators.
  - `verification_history/*` → Read restricted to administrators.
  - Write, update, and delete access across `claims`, `sources`, `evidence`, `news_articles`, and system settings restricted exclusively to administrators.
- **User Privacy**: `users/{userId}` is strictly readable and writable only by the owning user (`request.auth.uid == userId`) and super-admins.

## 5. Non-Destructive Migration Procedure

To migrate existing local and cloud datasets to this schema without data loss:

```bash
# Dry Run (Simulation)
python firebase/seed/migrate_schema.py --dry-run

# Active Persistence (Local JSON store)
python firebase/seed/migrate_schema.py

# Push to Live Firestore Instance (Requires .env credentials)
python firebase/seed/migrate_schema.py --live-firestore
```
